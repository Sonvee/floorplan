# 图片生成户型 JSON 任务文档

## 目标

编写一个可复用的 AI 提示词：输入户型图片后，只生成与 `assets/example/plan-demo.json` 兼容的户型 JSON 资源。再使用 `assets/prompt/plan-demo-image-1.png` 作为输入，生成对应示例 JSON 放入 `assets/example/`。

## 范围

- 只输出建筑户型：房间轮廓/名称、墙体、门、窗、滑门窗和尺寸标注。
- 严禁输出家具、家电、软装、人物、装饰物、地面纹理或图片说明文字。
- JSON 必须遵从 `assets/example/plan-demo.json` 的数据结构和单位约定；删除其中的 `furniture`，其余户型相关顶层字段及 `plan` 字段按 schema 保留。
- 生成文件必须是纯 JSON，不得混入 Markdown 围栏、注释、置信度字段或额外 schema。

## 坐标与尺寸规则

- 坐标单位为毫米，使用图片明确标注的总尺寸和分段尺寸校准几何，不把图片像素直接当作毫米。
- 建立单一、稳定的平面坐标系；所有墙、门窗、房间多边形及尺寸线必须落在该坐标系。
- 按样例中的墙体线段数组、窗/门对象、房间对象及 `dimensions` 对象的原始格式输出，不改字段名、顺序语义或枚举值。
- 只记录图中可辨认的几何和标注。不可辨认的局部应结合相邻边界作最小必要推断，不虚构尺寸或结构；若关键区域仍无法确定，生成后在任务报告中指出，不写入 JSON 注释或非 schema 字段。
- 房间轮廓应闭合、互不矛盾，并尽量与墙体和开口位置对齐；墙体应覆盖外轮廓及可确认的室内隔墙。

## 参考图识别要点

参考图带有网格和毫米标注。上方整体水平尺寸为 10750 mm，下方整体水平尺寸为 12330 mm；左侧整体垂直尺寸为 11040 mm。图形为带凹凸边界的住宅平面，含卧室、卫浴、洗衣阳台、厨房、餐厅、过道、客厅及休闲阳台等空间。图片中的床、柜、洁具、厨具、桌椅、沙发、茶几、植物等均须忽略。应优先辨认粗线墙体、红色结构墙段、蓝色窗/落地窗、门扇开启弧线及标注尺寸。

注：以上用于定位图片内容；最终 JSON 的具体几何和尺寸仍须逐段根据图片及样例 schema 编制，不得只凭空间名称猜测。

## 执行步骤

1. 阅读样例 JSON 与相关编辑器 schema，记录实际字段、枚举和数组结构。
2. 编写提示词，明确输入/输出、家具排除、尺寸校准、坐标一致性、schema 和不确定信息处理。
3. 依据提示词分析参考图，生成纯户型 JSON 至 `assets/example/plan-demo-image-1.json`。
4. 对照样例 schema 和参考图静态复核；发现字段、几何或排除项不合格时，先改进提示词，再修订示例 JSON，直至达到下列验收标准。

## 验收标准

- 提示词可独立指导模型处理类似户型图片，并明确要求只返回纯 JSON。
- 示例 JSON 可直接作为样例户型资源使用，顶层及嵌套结构兼容 `plan-demo.json`。
- 不含 `furniture`，且不把任何家具、家电、软装或装饰物编码为户型实体。
- 含可识别的房间多边形、墙体、门窗/滑门窗和尺寸标注；尺寸单位及坐标一致。
- 不添加 schema 不支持的字段，不用说明文字污染 JSON。
- 按仓库规则，AI 不运行测试、构建、验证脚本、应用或浏览器；仅进行静态文件与图像对照。由开发者手动验收导入效果。

## 交付物

- `assets/prompt/PLAN-IMAGE-TO-JSON-TASK.md`：本任务约束与验收基准。
- `assets/prompt/plan-image-to-json.md`：可复用提示词。
- `assets/example/plan-demo-image-1.json`：由指定参考图识别生成的户型 JSON。

## 当前待复核项

- 若仅凭图片无法可靠还原某个局部，不能把推测包装成确定尺寸；需在交付说明中列出，供开发者导入后人工确认。
