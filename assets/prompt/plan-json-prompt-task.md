# 户型图转设计资源 JSON 提示词：工作任务文档

## 1. 目标

在 `assets/prompt` 下编写一份可由用户复制、并与户型设计图一起提交给多模态 AI 的提示词。提示词的目标是：

1. 让 AI 从户型图中识别可编辑的户型资源；
2. 输出与本项目 `assets/example/plan-demo.json` 兼容的设计资源 JSON；
3. 尽可能保留图中的墙体、门窗、房间、尺寸标注、家具、家电与材质信息；
4. 在看不清或无法确定时显式采用保守推断，而不是编造不受图像支持的结构。

## 2. 输入

- 一张户型设计图；
- 用户复制本任务产出的提示词；
- 图像可能包含中文房间名、尺寸标注、家具名称、材质色块、墙体类型与门窗开启方向；
- 示例图：`plan-demo-image-1.png`、`plan-demo-image-2.png`。

## 3. 输出契约

输出必须是纯 JSON，不得包裹 Markdown 代码围栏或解释性文字。顶层字段固定为：

- `furniture`: 家具/家电数组；
- `plan`: 户型几何对象，包含 `walls`、`wins`、`doors`、`slides`、`rooms`、`dimensions`；
- `rooms`: 以房间 ID 为键的房间设置对象，至少包含 `name`、`mat`；
- `demolished`: 拆改墙数组，没有拆改信息时为空数组；
- `measures`: 用户测量线数组，没有测量线时为空数组。

项目坐标单位为毫米（mm），坐标原点和 Y 轴方向应在提示词中固定并说明。家具中心点使用 `cx`、`cy`，尺寸使用 `w`、`d`，旋转使用角度 `rot`。

## 4. 必须覆盖的识别内容

- 外墙、承重墙、普通墙、矮墙；
- 普通窗、落地窗、飘窗、滑动门窗；
- 室内门、入户门、开启方向、铰链方向；
- 房间闭合多边形、稳定 ID、名称、地面材质；
- 家具和家电的类型、名称、中心点、尺寸、旋转角度、颜色；
- 图中可读的总尺寸、分段尺寸和尺寸链；
- 不确定信息的置信度与保守处理原则（但最终 JSON 不能添加项目不支持的顶层字段）。

## 5. 迭代流程

1. 先阅读项目 JSON 示例和家具/材质/门窗类型目录；
2. 编写第一版提示词；
3. 使用两张示例图按提示词生成一份代表性 JSON；
4. 将产物与 `assets/example/plan-demo.json` 做静态字段、结构、坐标单位、类型与覆盖范围对照；
5. 把发现的缺口回写到提示词；
6. 再生成/修订对照 JSON，并记录最终仍无法从图像可靠确认的内容。

## 6. 验收标准

- 提示词可直接复制给支持图像输入的 AI 使用；
- 明确要求纯 JSON，且 JSON 顶层和嵌套字段与项目契约一致；
- 明确禁止幻觉式增补、禁止改变坐标单位、禁止使用项目未支持的家具类型和材质键；
- 对门窗、门、房间多边形、家具中心点和尺寸给出可执行的识别规则；
- 能处理无尺寸图、文字模糊、图像裁切和多个候选解释；
- 任务文档记录提示词文件、对照 JSON 文件和差异结论。

## 7. 预期产物

- `assets/prompt/floorplan-to-design-json.md`：最终可复制提示词；
- `assets/example/plan-demo-prompt-output.json`：基于示例图和提示词整理的对照产物；
- 本文档末尾追加迭代记录与静态对照结论。
## 8. 迭代记录

### 第 1 轮：契约静态对照

- 两张示例图展示的是同一户型方案；图中可辨识 11 个空间、外/内墙、门窗、尺寸链及多类家具家电。
- 与 `assets/example/plan-demo.json` 对照后，第一版提示词虽要求所有顶层字段，却没有定义 `demolished` 的 `wN` 索引语义，也没有定义 `measures` 的端点对象结构；这会导致生成结果字段齐全但内容形状不兼容。
- 第一版还要求必要时读取家具目录，但用户实际只需复制提示词并附图，因此已将家具库现有类型白名单直接写入提示词，避免模型自由发明 `type`。
- 已据此修订提示词：补充 `demolished`、`measures` 的精确结构及家具类型白名单；并强调示例 JSON 仅是格式参考，不能把其户型内容照抄到其他图片。
- 对照 JSON 已保存为 `assets/example/plan-demo-prompt-output.json`。如实说明：两张图与 `plan-demo.json` 是同一户型；为避免伪称模型完成了独立像素测绘，该对照产物以现有示例作为坐标/项目格式校准底稿，并重新生成家具 ID。它适合进行结构与语义覆盖对照，不代表独立 OCR/视觉测量精度评测。\n- 复看提示词后发现 L 形户型没有必然存在的左上外墙角，故将原点规则改为“选清晰、可定位的基准点”，避免把空白包围框角设为实体墙角。\n- 静态比对结论：字段形状、墙体/门窗/门/房间/尺寸链、家具数量与主要布置均能对应；提示词迭代中补上了原先欠缺的 `demolished` 索引语义、`measures` 端点结构和独立家具类型白名单。图片视觉判断仍不能保证逐像素复原，模糊门扇方向及隐蔽墙体应由提示词按保守估算处理。

### 尚需开发者手动确认

本仓库要求 AI 不得执行测试、验证、构建、运行或浏览器检查。本次仅对已读文件与图片进行静态对照，没有运行项目或验证脚本。建议开发者手动将 `floorplan-to-design-json.md` 与 `plan-demo-image-1.png` 一起提交给目标 AI，再检查输出能否导入编辑器；如有不兼容字段，可据实际错误继续修订提示词。
